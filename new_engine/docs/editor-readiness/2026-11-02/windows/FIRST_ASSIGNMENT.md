# Day one — learn, inspect, and report

Do not begin by rebuilding the city. Learn the system and establish what is
already available with the owner.

1. Launch the city, jungle and Grandstone separately. Review each area's starting
   view, camera controls, outliner, asset browser, Inspector, materials and VFX.
2. In a separate work folder, practice with one small prop: add, frame, move,
   rotate, copy/paste, End to ground it, Undo and Redo. Use full rotation/axis
   scales once to understand the Inspector. Confirm the copy is actually visible.
3. Try one VFX preset, preview pause/scrub/solo, and remove it. Inspect a material
   and understand which edits affect an entire shared asset alias.
4. Apply and save. Close and reopen the work folder, then check the saved result.
5. Export a small practice return with Return_Changes.bat. The owner should stage
   and review that return before assigning production work.
6. Send three screenshots per area and a short list: strongest areas, visible
   problems, editor friction, missing assets, proposed first 50–100 metre pass.

Read the architecture/collision and source-chunk limits in ARTIST_START_HERE.md.
Use existing assets to explore; hold new purchases, hero replacement, large
terrain edits and structural reorganization for the agreed art brief.

Acceptance for orientation: all three intended projects open on your Windows
machine, editor controls respond, the practice prop survives save/reopen, and
the owner can validate the small return. Record GPU, resolution, graphics preset,
any missing textures, and log files. Visual approval and sustained performance
are separate decisions from completing this orientation.
