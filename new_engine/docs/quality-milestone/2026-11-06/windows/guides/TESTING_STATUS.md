The package manifest binds the exact editor executable, matching native document validator, Python inventory/export helper and project payload. The four environments are retained; the apartment/arrival seed contains the current quality milestone. This edition includes the terrain worker pause/invalidation changes, improved camera navigation, independent vegetation layers and pond basin provenance.

Detailed build and acceptance evidence is kept with the owner. Check the release's verification receipt for the exact native/Wine test scope. A successful archive check verifies every stored CRC/SHA and the runtime/project manifests; it does not certify performance on every PC.

Physical Windows GPU/controller/performance acceptance remains pending until the receiving computer completes these checks. Committed generated tree trunks and rocks block walking; grass and low plants remain visual. Source structures with separate cooked collision remain protected against unsupported edits; there is no automatic structural recook.

## Check on the designer's Windows computer

1. Extract everything into a new writable local folder and run Valwood World Designer.exe.
2. Open one area and allow its seed/workcopy preparation and initial scene load to finish.
3. Confirm visible textured terrain, vegetation and buildings, responsive camera movement and wheel zoom.
4. Paint a short raise/lower stroke and separate grass/tree layers. Test walking against committed tree trunks/rocks. Place, resize, move and delete a new pond; confirm its former ground restores. Draw a river on clear ground. Undo and Redo each.
5. Apply/save, close and reopen. Confirm the edits remain and ground/water align while walking.
6. Tour the city, jungle and Grandstone. Check representative stairs and doorways in game view.
7. Save/close and run Return Saved Changes. Confirm a new return folder opens.

For failures, preserve the workcopy and send `logs/editor-latest.log`, the frontend status, a screenshot and what you clicked. Frontend logs are beside the delivery under `<delivery>_Work/Logs`.
