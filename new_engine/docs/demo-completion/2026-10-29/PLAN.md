# Integrated demo completion pass

Preserve the immutable Valwood Demo Polish package and existing user project files. Work in source and create a fresh package after validation.

1. Connect bounded authored NPC memory to real conversations and deterministic choices. Capture witnessed player interactions, repeat visits and training results. Keep private knowledge private; bind explicit scene entities rather than repeated names. No inference, network or allocations in frame ticks.
2. Create a repeatable demo journey: talk with master of arms, complete directional sparring, visit the jungle steward and return. Add visible journal/reward feedback and actual persistent player, quest, encounter, living, physics and NPC experience state. Save/load at explicit boundaries, transactionally; include Play rollback.
3. Refine the jungle landforms and surface transitions using existing models and baked material fields, preserve safe walking/water/camp zones, and retain original placement identities. Validate slopes, supports and route clearance.
4. Inspect supported character/combat transitions, improve discontinuities and foot contacts without inventing unsupported facial rigs or pretending descriptors create new meshes.
5. Profile matched full first/third-person walks at the saved quality and investigate expensive stages/spikes. Keep rejected runs and report the every-frame floor separately from average/1% low.
6. Validate the playable loop, saves/reload/corruption rollback, rendering and portable startup. Deliver a new separate package, screenshots and guide with measured results and remaining production limits.

Completion means the above concrete demo features work and are reviewable. It does not mean the entire 100 km game or AAA content production is finished.
