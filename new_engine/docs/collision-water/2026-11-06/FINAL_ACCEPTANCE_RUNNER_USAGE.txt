Generic final acceptance preparation (root use; no commands executed here)

No v8 binary, plan SHA or package is pinned by these helpers. Supply the exact
READY runtime/BUILD_PLAN SHA and new package receipts after the clean freeze.
All earlier v6 helpers and reports remain unchanged.

For EACH native and Windows runtime, first inspect the CPU-only plan:

  python3 docs/collision-water/2026-11-06/run_final_acceptance.py \
    --revision v8 --platform PLATFORM --runtime ABSOLUTE_RUNTIME \
    --plan-sha256 EXACT_BUILD_PLAN_SHA256 --phase core

Only root adds --run to execute GPU work. The core phase serially runs:
structural edit/Apply/Undo/Redo/save/reopen; source-floor NPC placement/path and
reopen; complete water authoring and reopen; three actual water close-ups;
Grandstone's fast four-route/eight-direction traversal; Jungle smoke.

For revision v8 and later, actual R12/depth1 Pond creation is mandatory:
after the complete Water QA and reopen, the CPU-only v8 Pond helper checks the
real viewport creation log and unchanged saved pond recipe before visual GPU
capture, then binds all three actual images afterward. The helper SHA and
both provenance receipts are recorded in the run plan/aggregate. The finalizer
rechecks the receipts and reruns only this known CPU provenance helper. The
--pond-preset-v8 flag enables the same requirement for an earlier revision;
v8+ does not need the flag because the requirement is automatic.

The same command with --phase journey --run runs the full apartment cinematic,
TV new-game, transport, all three travelers, combat/defeat/retry, once-only
reward and town checkpoint save/restore. It creates a new platform/revision
reference project and uses the frozen plan-selected guarded water shader patch.

Each run refuses existing project/evidence paths, verifies actual source,
binary, READY, all41 Windows closure files where applicable, protected water
helpers and every collision payload file before children and again afterward.
Child failures stop the queue and preserve raw evidence. Core reports are
ACCEPTANCE-PLATFORM-core-v8.json; journey reports use -journey-v8.json.

The CPU-only finalizer takes the actual new candidate paths, not older defaults:

  python3 docs/collision-water/2026-11-06/prepare_finalization_v8.py \
    --revision v8 \

    --protocol NEW_PROTOCOL_RECEIPT --payload-proof NEW_PAYLOAD_PROOF

full journeys, exact new package protocol and collision receipts, and reopens

evidence directory, raw-backed full-journey installer adapters, release-note
