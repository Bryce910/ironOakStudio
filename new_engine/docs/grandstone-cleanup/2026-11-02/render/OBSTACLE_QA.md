# Native stair and doorway regression

`engine/world_grandstone_obstacle_qa.inc` is enabled only by the explicit, frame-gated `VALWOOD_QA_GRANDSTONE_OBSTACLES` flag. It runs after the ordinary playtest callbacks are available. The nine sealed source paths in `engine/world_grandstone_qa_cases.h` cover two open hall doorways, lower and upper stair flights on both sides, two Barbican stair routes, and the complete exterior descent around its source rock intrusion.

All route movement calls the actual `move_camera` adapter, retaining the source triangle controller, scenery, residents and runtime actor checks. Both directions total 555.548773235 m; the optional Windows quick subset covers both open doorways, the right lower hall flight and the north Barbican stairs, totaling 95.834523779 m. Movement is bounded to the ordinary sprint speed per 1/60 s step. Any collision flag, terrain-slope flag, dropped displacement, lost grounding or unsupported storey fails immediately. Each reached node checks its accepted source feet and performs two repeated support samples to reject drift.

Each independent path begins with an explicit, logged setup teleport to an accepted source floor. This is not a continuous journey through the full imported castle. Both closed gates are tested from both sides using actual `move_camera` attempts. An ordinary 4.7 m/s jump then uses 9.81 m/s² gravity and the actual `move_camera_vertical` adapter, checks source overhead geometry and returns to the supported floor. The sidecar separately reports whether that jump actually contacted a ceiling; a source ceiling ray alone is not a ceiling-impact claim.

One actual final-HUD screenshot is captured at each forward endpoint before the reverse traversal. This readback runs only in QA and does not affect ordinary game performance. Images are saved as BMP and losslessly converted to PNG by the runner. The normal final engine frame captures the supported jump landing. Captures and held endpoint frames are included in timing, so these results are not a sustained frame-floor benchmark.

Run `python3 -B tools/check_grandstone_cleanup.py --binary build/grandstone-cleanup/bin/rpg --output NEW_EVIDENCE_DIRECTORY`. The Windows check accepts `--wine --fast` and an explicit owner-built `.exe`. The runner uses only `build/grandstone-cleanup/qa/grandstone/project`; it rejects shared saves/AI/settings and fingerprints the original source projects, user playtest saves, sealed QA route/physics inputs and executable. It validates measured distances, per-node counts, gate outcomes, jump landing, camera near plane, hardware rendering, resource shutdown and streaming results before reporting a pass.

Runtime evidence remains required. Compilation or the runner's own positive/negative fixture check does not establish that the native obstacle workflow passed.
