# Accepted source baked-diffuse correction

The first-landing screenshot initially showed a large black underside above the hero. Source and active-native mesh rays identify the downward stair faces and their `M_Pillar_stone_03` material. Their normals face downward correctly, their base texture is present, and their stored source irradiance is positive. A representative native sample has irradiance `(5.05, 1.08, 0.19)` with validity 1, but its material ARM sample has AO `1/255`. The previous shader multiplied the already-baked room transport by that occlusion again, almost erasing it.

The accepted private shader keeps material AO on the existing native environment and specular terms. Its baked-diffuse replacement uses the actual source irradiance once. Direct sunlight, practical lights, exposure, textures, normals, models and collision data remain unchanged. The 10,000-sample CPU algebra check confirms that its only diffuse difference is `diffuseBRDF × sourceIrradiance × bakedWeight × (1 − materialAO)`; surfaces with AO 1 and surfaces without valid baked light retain the earlier result.

The unchanged native executable passed the four-path comparison: both open hall doorways, the right lower hall stair flight and the north Barbican stair route, in both directions, totaling 95.834524 m. Both closed gates still blocked movement from both sides, and the ordinary gravity jump returned to its supported floor. Resource, hardware rendering, runtime, shader and original-state guards passed. The separate nine-path native movement certificate covers 555.548773 m with the same collision/controller data.

I reviewed the actual four endpoint screenshots against the previous native captures. The first stair underside now receives warm room light, the doorway stone detail and frame coverage remain clear, and the hero silhouette remains visible. In an interior underside region from display pixels `(650,200)` to `(1000,340)`, exact-black coverage dropped from 87.47% to 0%; mean RGB changed from `(0.13,0,0)` to `(107.13,30.95,6.70)`. These measurements read the unchanged screenshot pixels; no image enhancement was applied. `accepted-review.json` records both image hashes.

The original underside mesh is still a broad, plain surface. Some roof recesses remain dark because their source lighting is dark. This is a visible improvement and a measured regression pass, not a claim of complete visual perfection or a sustained frame-rate floor.

The accepted shader SHA-256 is `d62cf5aeba53a0f326ded73012bcadc91af522edc4d06605d4f23a9bc3fe5c49`. Only the isolated QA project's `shaders/world_foliage.fs.glsl` was installed at this point; `qa-install.json` records its guarded old hash and backup. The original source project and the user's current playable project still have their previous shader. Later acceptance and packaging must bind this exact private file before delivery.

Subsequent native and Windows/Wine combat checks passed using that default QA project shader, with no candidate override. I reviewed both final hall captures: the armed hero remains visible, masonry and floor detail remain legible, and no new frame clipping or uniform ambient wash is apparent. `accepted-review.json` records these later report and screenshot hashes. The Windows run used this Linux host under Wine; it is not acceptance on the designer's own Windows computer.
