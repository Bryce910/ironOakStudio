# Full-resolution linear texture blocks

The loading path now admits offline BC7 normal maps and ARM maps without changing authored texture dimensions or discarding mip levels. Missing, corrupt, mismatched, low-quality or unsupported caches retain the original full-resolution RGBA path. No encoder, GPU readback or cache writing runs while playing.

- Format 1 remains opaque sRGB BC7, unchanged.
- Format 2 is linear ARM data. Every mip must have byte RMSE ≤1.5, channel maximum error ≤6, absolute mean bias ≤1.5 and alpha exactly 255.
- Format 3 is linear normal data. It also requires maximum angular error ≤2°, maximum per-mip angular RMS ≤0.75°, and source/decoded vector squared lengths ≥0.04. Its binary header carries conservative angular bounds rounded upward to 1/1024°. Old format-2 files cannot satisfy a normal request.

All formats validate complete original encoded source identity, CRC64 over metadata/source/blocks, exact full mip chains, bounded dimensions, opaque BC7 recipe modes and per-mip quality before upload. The checksum detects accidental corruption; it is not an authenticity signature. Role-specific cache keys prevent a generic ARM certificate from being reused for a normal map with identical encoded bytes. Both immediate and CPU-prepared/staged loaders use `GL_COMPRESSED_RGBA_BPTC_UNORM` for linear data; color uses the sRGB variant. Facade auxiliary normal/mask/ARM maps remain exact RGBA8.

`/tmp/valwood-cook-texture-blocks --models PROJECT/models --output PROJECT/texture_blocks --linear` cooks linear candidates, using `.linear.vbc7` filenames. It classifies every encoded image used by a normal slot as a normal candidate before deduplicating. A preexisting format-2 normal cache is recooked even without `--force`; rejected candidates remove their cache and retain the original. Opaque color cooking remains the existing command without `--linear`. The cooker must run separately from performance acceptance.

Managed catalog revisions locate `texture_blocks` beside their model files. The showcase builder must provide each revision's `texture_blocks` symlink to the shared project cache directory. The source PNGs and GLBs remain unchanged.

CPU checks: `make test-world-texture-blocks-format test-world-model-linear-blocks-cpu`. Native fixture: `VALWOOD_TEST_NATIVE_GL=1 make test-world-model-linear-blocks-gl`. The latter generates a small real PNG/GLB, encodes all three mips, independently checks decoded angle/data errors, then exercises immediate and staged native uploads, format-role rejection, original fallback after a real invalid compressed upload, exact GPU byte accounting and ownership cleanup. It does not establish sustained gameplay performance or the final scene's memory total.

Verified 2026-11-01: container CPU 584 checks; production CPU preparation 88 checks; native GL 92 checks on AMD Radeon RX 5300 (radeonsi, navi14). The same GL fixture also passed llvmpipe separately. Immediate and staged loaders used the linear BC7 internal format, role mismatches retained original RGBA, tracked 144 bytes for compressed+original+neutral images, and tracked 180 bytes after an injected real invalid compressed upload caused full-original fallback. All owners released and no GL error remained.

The world profile's `texture_blocks` counters have scope `cumulative_immediate_upload_attempts`: they count immediate-loader cache attempts and successful BC7 uploads during that process lifetime. `cached_textures` is not current resident textures or unique source images, and these counters exclude CPU-prepared/staged cache admissions. The 8-layer showcase terrain arrays are separate. The profile records full-resolution/full-mip preservation, certified linear admission, original RGBA upload paths for masked color maps and facade auxiliary linear data, and no runtime encoding. It does not claim that all linear maps are unchanged. Historical profile files retain their older field; the validator accepts that legacy schema for compatibility without treating it as new certificate diagnostics.
