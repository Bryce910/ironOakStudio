# Publisher scene startup residency

The initial source-scene capture ran at 14.22 FPS with 2,883,461,120 bytes peak aggregate VRAM usage. This was a functional capture, not performance acceptance. Its runtime report confirms 32 village pet pose assets resident with zero pets visible, while wildlife, bandits, trail camp and dragons had zero pose assets and zero bank loads.

`unused-startup-assets.json` counts actual GLB node/accessor data and embedded image dimensions. The unused procedural dressing, horizon cards, coastal cliff and pets total 77 model load calls, 29.18 MiB of current vertex/index buffers and 587.74 MiB of distinct uncompressed mipmapped images. Image counts deduplicate encoded bytes and color space; sampler policies and sharing with retained objects can affect actual savings. A fully compressed hypothetical image floor is 146.97 MiB, not a claim that every cutout/data image has a valid BC7 cache.

With root authorization, `engine/world_viewer.cpp` now skips initialization, update/selection, drawing and probe preparation/restoration for the three old procedural scenery systems only when `publisher_showcase.json` exists. Empty probe helpers return success. Village pet loading is disabled for the same source project. Purchased source-scene foliage is unaffected. Player/controller, dwarves, snow, weather, source terrain and streamed scene geometry remain enabled; ordinary projects retain their existing paths.

The source project's private terrain main samples its eight authored PBR layers and a separate fallback material. It does not call the inherited village ground-history helpers. A second source-only early return in `LandscapeMaterials::init` keeps mask arrays, starting mask, roof metadata and directional metadata, and skips the old five-layer 2048² litter array (106.67 MiB), three-layer village stone array (64 MiB), and 2049² history texture (21.35 MiB). `uForestGroundReady` now reflects actual litter readiness. These three uploads account for another 192.02 MiB. Existing direction volume allocation was deliberately retained.

Verification was CPU-only source inspection: all 16 procedural helper gates plus the pet gate are present; omitted landscape textures are absent from the private terrain `main`, and ground-history helpers have definitions but no callers. No native build or GPU measurement was run by this subagent; root owns final compilation and comparative capture.

# Source sky and grading

The raw source panorama is kept linear and unmirrored. Native rotation **+154 degrees** matches source spherical coordinates after Unity-to-engine Z reflection: Unity rotates sky geometry while retaining unrotated texture coordinates, so the inverse ray rotation and reflection cancel. `sky-grade-orientation-audit.json` compares both coordinate formulations over 10,000 normalized random rays with wrapped UV error below 1e-12. This verifies the analytic spherical convention; it is not a live Unity cubemap-import image comparison. The [official Unity sky shader](https://raw.githubusercontent.com/Unity-Technologies/SkyboxPanoramicShader/master/Skybox-PanoramicBeta.shader) supplies the reference mapping.

Source `PostProcessVolumeProfile Castle.asset` uses HDR ACES, post-exposure zero, gamma trackball W=-0.09394813 and gain W=-0.122690946. Their effective inverse gamma is 1.1036895713 and gain is 0.877309054. Lift, stored hue shift, saturation and contrast overrides are disabled and remain neutral. The [official Unity conversion utility](https://raw.githubusercontent.com/Unity-Technologies/PostProcessing/v2/PostProcessing/Runtime/Utils/ColorUtilities.cs) and [HDR grade shader](https://raw.githubusercontent.com/Unity-Technologies/PostProcessing/v2/PostProcessing/Shaders/Builtins/Lut2DBaker.shader) place this grade before tone mapping in ACEScg. The engine's current RGB filmic fit is an approximation of that full color-space/tone-map pipeline, so matching these coefficients alone does not establish image parity.
